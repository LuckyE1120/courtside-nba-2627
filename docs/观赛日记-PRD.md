# 观赛日记 PRD（2026–27 赛季）

## 目标与范围

让用户在每日赛程中选择看过的比赛，记录心情、文字与照片，并获得基于本人记录的定期 AI 日记。赛程和比分对所有访客开放；私人记录登录后跨设备同步。首期不提供公开分享、社交互动或多人共同编辑。

## 核心流程

1. 用户打开比赛日，在观赛日记页点一场比赛，弹窗显示对阵和比分。
2. 用户可选一个 Emoji 心情、点击预设文案后继续编辑，或直接写 1000 字以内的感受。登录后可添加最多 3 张 JPG、PNG、WebP 照片，每张不超过 2 MB；保存后可重新编辑或取消圈选。
3. 未登录不能保存观赛记录；注册、验证邮箱并登录后，记录保存在账号云端。用户可导出或导入 JSON 文字备份，图片原文件不包含在备份中。
4. 用户选择周记或月记、查看周期，点“生成 AI 日记”。生成输入仅包含该周期圈选比赛的日期、对阵、比分、心情和笔记，不包含照片。日记可重新生成。
5. 每日北京时间 10:00，后台检查上一完整周或月；有观赛记录且未生成过的周期自动生成日记。已有日记不自动覆盖。

## 数据和权限

`journal_profiles` 存用户周/月偏好；`watched_games` 按用户和比赛去重；`diaries` 按用户、周期和起始日期去重。三张表启用 RLS，登录用户仅能读写自己的记录。`journal-images` 为私有桶，文件路径以用户 ID 开头，读写删除权限仅授予所属用户。DeepSeek Key 仅存 Edge Function Secret；定时令牌由数据库随机生成并放在 Supabase Vault 中，不放入 GitHub Pages。

## 状态与异常

赛程快照与实时比分分开显示，实时数据缺失时提示可能延迟。未登录不能保存观赛记录、上传照片或调用 AI。图片格式、大小、数量在客户端和存储桶分别限制。AI 密钥无效、余额不足、模型超时或返回不完整内容时显示错误，不能覆盖已有日记。定时任务单用户失败不应中断其他用户。

## 验收标准

- 每日比赛可点击打开记录弹窗，Emoji、预设文案及手写文字保存后重开仍在。
- 登录后可跨刷新读取自己的记录；匿名 REST 请求看不到他人的记录；另一账号不能读取私有照片。
- 合法照片可上传、显示并删除；超 2 MB、伪造 MIME 或非支持格式被拒绝。
- 手动生成只使用圈选的已记录事实，不发送图片；生成结果保存并可在刷新后查看。
- 定时调用能在网页关闭时触发，返回成功计数；同一周期重复运行不生成第二篇，也不覆盖用户手动生成的内容。
- 旧站文字记录和已有日记可迁移，迁移前后数量核对一致。
